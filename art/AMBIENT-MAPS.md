# Noct：四区域环境微动态与接入说明

## 已接入的试玩版

现有项目使用原生 JavaScript / Canvas 2D，不是 Godot 或 Unity。本轮保留家园、账号存档、狐狸四方向和待机动画、自动攻击及暂停属性面板，新增：

- 家园入口的四地图选择；失败可重试，地图加载成功后才消耗暖汤。
- 2048 × 1280 世界坐标、640 × 400 可视画面、边界约束的跟随镜头与小型方位图。
- 已确认的原始图片为 **1586 × 992 px**；保留 PNG 原稿，线上使用质量 98 的 WebP。世界坐标变大并不代表图片产生了新细节，也不是把角色缩成原来的三分之一。
- 固定障碍、边缘水域/熔岩/裂谷碰撞，桥面保留通道。敌人使用低频共享距离场绕行；掉落资源只布置在可达区域。
- 3:00 暂停并选择撤离或继续，4:00 自动结算；现在撤离获正常完成奖励，完成额外一分钟再得木材 4、石材 2、星光 3。死亡仍保留已拾取资源，不改变轻松经营的定位。
- 环境动态可在探险暂停菜单开关；遵循系统“减少动态”。暂停、升级、撤离选择期间环境时间冻结。

本轮的冰面/浅水表现是视觉效果；未擅自加入打滑、减速、熔岩灼伤。撤离仍通过菜单完成，没有另加必须跑到地图角落的撤离条件。

## 重要素材边界

这四张图是**合并后的底图**，没有独立的树、根部下方地面、莲叶底下水面等透明图层。目前采用人工指定区域 + 颜色遮罩 + 羽化边缘的局部变形和叠加：树冠内部与草叶纹理有微动，根部和地形轮廓保持固定。它不是完整拆分后的 Sprite Sway，不能宣称已获得无缺口的独立树冠动画。

图中没有明确的森林瀑布、熔岩瀑布，也没有雪原松树林，因此本轮**不凭空添加**。现有溪流、池水、熔岩表面和少量雪地枯枝已做对应微动态。未来添加瀑布或松树时，需单独准备透明素材和干净底板，再接下面的同类动效。

## 动态元素与参数

下列位移以游戏逻辑像素为单位（640 × 400 可视画面）。节奏均为起始调参值，不是所有设备上的性能保证。

| 区域 | 元素 | 当前 Canvas 实现 | 参数与限制 | 完整分层后的建议 |
|---|---|---|---|---|
| 月影森林 | 草叶 | 局部条带水平采样偏移，底部权重归零 | 0–1 px，6–8 秒，各簇不同相位 | 根部固定的 Sprite 顶点/UV sway |
| 月影森林 | 树冠、灌木 | 小范围羽化遮罩内的纹理微变形 | 0–1 px，7–9 秒；不移动树干、碰撞 | 独立树冠网格 + 根部权重 |
| 月影森林 | 溪水、波纹 | 水色遮罩内条带微扰、缓慢移动高光 | 扰动 1 px，10–12 秒；高光约 2 px/秒；桥面固定 | 双层可平铺水纹 UV scrolling |
| 月影森林 | 蘑菇、晶石、月门 | 小半径柔光叠加 | 7–10 秒；叠加透明度约 3.5%–6.5% | 发光遮罩 × 正弦波，避免全屏 Bloom |
| 月影森林 | 萤火 | 有限数量的世界坐标粒子 | 同屏上限 14；低透明度，避开狐狸 52 px | 粒子系统，固定随机种子，错峰寿命 |
| 荧光湿地 | 芦苇、水草 | 根部衰减的局部微偏移 | 0–1 px，7–9 秒 | Vertex sway，顶端权重大、根部为零 |
| 荧光湿地 | 浅水、栈桥旁水流 | 只在水面颜色遮罩内移动纹理 | 10–13 秒；水岸与木桥不扭曲 | 水流方向遮罩 + UV scroll |
| 荧光湿地 | 莲叶 | 指定小区域上下采样偏移 | 最大 1 px，10–12 秒 | 独立 Sprite 上下浮动，底板补全 |
| 荧光湿地 | 荧光植物、蘑菇 | 柔光慢呼吸，不做突兀随机闪白 | 8–11 秒 | Emission mask × smooth sine |
| 荧光湿地 | 荧光粒子 | 世界坐标低亮粒子 | 同屏上限 16，角色附近淡出/避开 | 粒子系统，无碰撞、无灯光 |

| 星落雪原 | 冰湖、冰面 | 冰色遮罩内极轻高光变化 | 16–19 秒；不让整片雪地闪烁 | 局部高光遮罩 + 低幅噪声 |
| 星落雪原 | 枯枝 | 极慢局部微扰 | 最大 1 px，14–15 秒 | 有松树素材后可同法处理独立树冠 |
| 星落雪原 | 冰晶、星落晶石 | 局部淡紫/冷蓝光呼吸 | 12–14 秒；比森林更慢 | 局部发光 Shader |
| 灰烬峡谷 | 熔岩池、裂缝 | 熔岩色遮罩内微扰和慢高光条带 | 扰动 1 px，12–15 秒；高光约 1 px/秒 | 双向熔岩 UV + 明暗遮罩 |
| 灰烬峡谷 | 熔岩边缘、赤晶 | 局部暖光呼吸 | 7–11 秒；保持蓝紫地面，不把全屏染红 | Emission mask × smooth sine |
| 灰烬峡谷 | 局部热扰动 | 只重采样熔岩底图小区域 | 最大 1 px，14–15 秒；不采样角色/UI | 背景专用渲染纹理内的热扰动 |
| 灰烬峡谷 | 火焰祭坛 | 小区域纹理和亮度起伏 | 最大 1 px，约 5 秒 | 独立 4–6 帧低速循环 Sprite |
| 灰烬峡谷 | 灰烬、少量火星 | 缓慢上飘，少数暖色粒子 | 同屏上限 14；不设碰撞或伤害 | 普通粒子系统，无真实粒子灯 |
| 灰烬峡谷 | 焦黑植被 | 本轮保持静止 | 避免所有元素同时运动 | 以后独立素材最多 0.5–1 px / 12–16 秒 |

“轻微闪烁”使用连续函数，不使用每帧随机数；不同对象使用不同相位，避免全地图同步呼吸。雪和灰烬的世界边界循环在镜头外发生。光点、雪花不使用与经验宝石相同的十字轮廓。

## 分层与遮挡

逻辑素材层：

1. **静态底图**：草地、雪地、灰烬地面、树干、桥、遗迹。永不摇晃。
2. **植被微动态**：草、水草、树冠、莲叶；专用权重遮罩。
3. **水 / 冰 / 熔岩**：分别使用不重叠遮罩，保持岸线固定。
4. **局部发光**：只覆盖发光物附近的地表，禁止环境全屏亮度脉冲。
5. **环境粒子**：数量受限，按镜头剔除；游戏内在角色之前绘制。

当前实际绘制顺序：底图 → 局部植被/水面 → 柔光 → 环境粒子 → 宝石与敌人 → 资源与狐狸 → 战斗特效 → UI。五个环境层不是五张全屏不断重绘的特效图。以后真正拆层后，需按脚底 Y 排序树冠与角色，避免仅用整张底图造成的前后关系限制。

**碰撞层永远独立于动画层**。根部与石块的碰撞轮廓不参与摇晃；视觉冰纹、装饰性地裂不自动变成伤害区域。敌人/狐狸都不使用整张 Sprite 的矩形作为地形碰撞。

## 当前实现的运行预算

- 游戏逻辑/角色继续按原有帧循环更新；环境局部纹理以 15 Hz 量化更新，使用时间函数而非累计像素移动。
- 只处理镜头覆盖的局部补丁；图片解码、颜色提取、遮罩制作仅在该地图第一次进入时执行。
- 不在每帧调用 getImageData；不创建每粒子的真实灯光；不引入全屏后期模糊。
- 碰撞地图仅 64 × 40 导航格；敌人共享低频距离场，附近目标有直接路径时直接移动。
- 粒子计数上限为每个当前画面，而不是每棵树一套独立粒子系统。
- 降级顺序建议：关热扰动 → 粒子减半 → 关植被变形 → 保留静态地图。当前已提供一键完全关闭环境动态。
- 高质量 WebP 用于减少首次传输体积，PNG 原稿保留；没有改动人物图集。

测试覆盖了四地图选择、地图边界与资源可达性、碰撞、屏外刷怪、动态时间冻结/开关、三分钟选择、四分钟结算，以及原有家园种植、建造、暖汤与存档。检查使用本地 Canvas 渲染和逻辑测试，不等同于真实手机/浏览器性能测量。

## Godot 4 落地思路

以下为移植设计，**并非本轮已迁移到 Godot**。

- `Node2D` 地图根节点；静态背景 `Sprite2D`；分层植被 `Sprite2D`；水/冰/熔岩各一组 `Sprite2D + ShaderMaterial`；`GPUParticles2D` 做稀疏环境粒子；`StaticBody2D + CollisionPolygon2D` 单独承载碰撞。
- 固定图像纹理过滤为 Nearest；先统一每单位像素数，避免角色与地图像素格大小漂移。独立树冠设置底部锚点，或用 Mesh2D 做顶端权重变形。
- 水纹 Shader 用 `uv + flow_direction * ambient_time * speed` 采样**可平铺纹理**；`fract` 只用于独立的可平铺水纹，不用于含桥梁的整张地图。岸线遮罩与发光遮罩在静态 UV 取样。
- 内建 `TIME` 不会随场景暂停自动冻结，因此由游戏控制器累加并传入 `ambient_time`，暂停/升级菜单不累加。所有对象加不同 `phase`。
- 热扰动只处理背景的 `SubViewport` 纹理，再在其上绘制角色、敌人和 UI；不要对最终游戏画面使用屏幕扭曲。

独立植被素材的 Shader 起点（未在 Godot 工程内验证）：

```glsl
shader_type canvas_item;
uniform float ambient_time = 0.0;
uniform float phase = 0.0;
uniform float period = 8.0;
uniform float amplitude_px = 1.0;
uniform sampler2D sway_mask; // white near tips, black at roots; sprite has padding

void fragment() {
    float weight = texture(sway_mask, UV).r;
    float wave = sin(ambient_time * 6.2831853 / period + phase);
    vec2 offset = vec2(wave * amplitude_px * TEXTURE_PIXEL_SIZE.x * weight, 0.0);
    vec4 texel = texture(TEXTURE, UV + offset);
    COLOR = texel;
}
```

发光计算起点：`strength = base + amplitude * (0.5 + 0.5 * sin(tau * ambient_time / period + phase))`。参数代表局部叠加强度，不是强制整张素材亮度变化。

官方参考：[CanvasItem Shader](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/canvas_item_shader.html)、[GPUParticles2D](https://docs.godotengine.org/en/stable/classes/class_gpuparticles2d.html)。

## Unity 落地思路

以下为移植设计，**本轮没有增加 Unity 工程依赖**。

- 使用 URP 2D Renderer 或现有 2D 渲染方案；`SpriteRenderer` 按 Ground / Ambient / Actors / CombatFX / UI 分层；固体使用 `PolygonCollider2D` 或 `CompositeCollider2D`，动画不改变 Collider。
- 独立水纹的 Shader Graph：`UV → Tiling And Offset → Sample Texture 2D`。Offset 来自自定义环境时间 × 方向 × 速度；水域遮罩限制到水面。
- 植被使用独立 Sprite 的局部 UV 微扰，或 Sprite 网格顶点位移乘根部权重；共用材质参数时可用 `MaterialPropertyBlock` 传相位，避免每株都实例化新材质。
- 发光用遮罩乘缓慢正弦波；不要用巨量 2D Light 逐个照亮粒子。若启用 Bloom，仅做很弱的辅助并检查宝石与敌人辨识。
- Snow / Firefly / Ash 各使用低发射率 Particle System，限定 `Max Particles`、World Simulation Space；暂停时显式暂停粒子与自定义环境时间，菜单关闭后继续原相位，不重置。
- 热浪需要背景专用 RenderTexture 或渲染 Pass，先变形地景再叠角色/UI。若当前项目的透明物体排序不支持隔离，先关闭热浪，不使用全屏扭曲代替。
- Pixel Perfect Camera 与 Point 过滤配合，最终仍需实机核对非整数缩放和边缘跳动。动画像素位移可量化，避免通过模糊掩盖锯齿。

官方参考：[Tiling And Offset Node](https://docs.unity3d.com/Packages/com.unity.shadergraph@17.0/manual/Tiling-And-Offset-Node.html)、[Particle System Main Module](https://docs.unity3d.com/6000.0/Documentation/Manual/PartSysMainModule.html)。

## 后续美术精修所需资产

若要从本轮的局部微变形升级到真正独立树冠、完整莲叶浮动和瀑布循环，应提供每图的干净地面底板、透明植被层、水面层、水域/流向遮罩、发光遮罩、独立静态遮挡层。拆分时必须补全被移动物体遮住的背景，不能只把树剪下来后让原位置留下空洞或双影。
